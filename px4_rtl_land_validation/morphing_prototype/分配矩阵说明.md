# 推力效能矩阵框架与验证边界

当前成果是可替换几何的计算框架，以及参考模型上的数学/运动学检查。`UAV.STEP`不是最终样机，与最终样机差异未知。所有数值结果均不得直接用于实机或最终样机PX4配置。

## 通用关系

采用机体FRD坐标：X向前、Y向右、Z向下。输出顺序为滚转/俯仰/偏航力矩，以及X/Y/Z合力。

给定当前构形q、旋翼相对于力矩参考点的位置r_i(q)（m）、实际推力方向单位向量d_i(q)、有符号反扭矩比k_i（m），单桨实际推力大小T_i（N）的矩阵列为：

```text
B_i(q) = [ r_i(q) × d_i(q) - k_i d_i(q) ]
         [             d_i(q)          ]

[tau_x, tau_y, tau_z, F_x, F_y, F_z]^T = B(q) T
```

输入是实际单桨推力，不是PWM、转速或油门百分比。参考点须显式给出；真实动力学通常需要当前整机重心，CAD原点不能默认就是重心。

若推力方向竖直向上，d_i=(0,0,-1)，可用下面的已知特例检查符号：

```text
B_i = [-y_i, x_i, k_i, 0, 0, -1]^T
```

本地PX4 v1.17的 `ActuatorEffectivenessRotors::computeEffectivenessMatrix` 计算的列为CT_i乘以上式。`module.yaml`定义物理模型T_i=CT_i*u_i²；不能将该列矩阵直接解释为原始油门u_i的线性映射。KM按PX4约定包含旋向符号，不应重复加一次旋向正负号。

## 当前演示夹具

- 使用参考STEP中的放置关系作为计算夹具，临时采用FRD与模型FLU转换；不是最终样机坐标或已实测推力作用点。
- 虚拟关节中心取FRD的(±45,±45,0) mm，H/V端点角均为25°，反扭矩比示例取±0.01 m。这些全部是**演示假设**。
- 一个演示输入q∈[-1,1]：q=0为X；q>0进入H分支；q<0进入V上反角分支。先回中立再切换，不假设H与V可同时独立控制。
- 镜像同角只是工具验证用近似，没有识别真实单舵机、卷盘、线缆和被动关节的传动关系。
- `effectiveness`函数可接收其他旋翼数量、位置、推力轴、反扭矩比和参考点。真实模型资料到齐后需替换输入，并重做全部核对。

## 已执行的数学检查

`kinematics.py`核对中立态、竖直特例符号、单位推力轴、独立向量求和与矩阵乘积一致，以及上反角的高度方向。示例X/H/V矩阵均为秩4。

四个推力输入最多提供四个独立控制方向。六行输出不意味着六自由度可独立控制。当前未实现满足非负推力、上限、动态与执行器约束的反向控制分配，也未分析真实构形全域的奇异性。

旋翼移动引起的重心/惯量变化、机臂运动惯性、弹性与绳索力等并不包含在这张静态推力效能矩阵中。它不是完整运动方程，更不是已验证的飞行控制器。

## 文件

- `allocation_demo.json`：示例三态矩阵、输入语义、所有假设与检查结果。
- `bench_assumptions.json`：Gazebo运动学夹具的近似与占位设置。
- `verification_X/H/V.json`：Gazebo测得的旋翼位姿与解析计算的比较，只有实际运行后才生成。
- `cad_inspection.json`：仅针对参考STEP的实体与几何读取结果。
