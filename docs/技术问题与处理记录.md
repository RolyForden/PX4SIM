## 1. 环境与运行

### Gazebo版本混用

**现象**：宿主系统已有Gazebo安装，但历史工程、ROS桥和当前Harmonic版本不同。

**定位**：历史素材使用Classic/ArduPilot；当前PX4运行于Harmonic容器。宿主ROS Humble的ros_gz_bridge面向Fortress。

**处理**：保留现有环境，Harmonic统一在`px4-rtl-land-harmonic`容器运行。早期ROS适配采用docker exec调用gz transport；活动关节联调改用原生gz transport辅助进程和回环UDP。

**后续**：正式ROS桥按Harmonic版本单独匹配。

### GPU配置与实际渲染不一致

**现象**：Gazebo窗口卡顿；容器同时存在NVIDIA配置和`LIBGL_ALWAYS_SOFTWARE=1`。

**定位**：容器环境变量和设备请求分别检查，实际渲染通过Ogre日志及GPU进程核对。

**处理**：GUI显式设置`LIBGL_ALWAYS_SOFTWARE=0`、`__GLX_VENDOR_LIBRARY_NAME=nvidia`，保留NVIDIA CDI设备和既有Docker配置。

**验证**：已观察到RTX4060实际渲染。飞行诊断采用无GUI服务减少桌面负载。

### 仿真启动配置影响闭环测试

**现象**：早期A刚体和标准模型诊断存在发散或运行异常。

**处理**：统一`GZ_IP=127.0.0.1`、Gazebo分区和4ms步长后，先恢复标准模型，再恢复A模型。

**验证**：A固定构形回归通过，见candidate_flight阶段记录。

**记录要点**：这是已验证的工作配置；此前多个启动条件一同调整，单一根因留待独立复现。

## 2. 设计资产与物理参数

### 参考模型与A整机混淆

**问题**：旧`UAV.STEP`与自研`A无人机.STEP`曾同时用于准备工作，容易混淆成果归属。

**处理**：A模型已确认为最新版本。旧参考台架及阶段记录移至`archive/`，A模型主线使用`a_morphing/`。

### 几何文件与关节模型的差异

**问题**：STEP提供几何和装配形状，柔性件的外形需要进一步转换为仿真自由度、驱动和材料响应。

**处理**：按部件分组建立机身和四臂，用等效yaw/pitch关节表达H/V运动；单个构形输入协调各臂，H/V经X切换。

**后续**：弹性回弹、滑块退让、绳索传动和舵机响应逐步加入模型。

### 质量与惯量来源不完整

**现状**：BOM总质量1.15682kg，0.393kg位置暂置CAD原点；5个CAD实例待补质量。部分BOM与CAD数量存在差异。

**处理**：参数集中在JSON/CSV，使用完整精度重心和带符号惯性张量。按运动部件重算构形质量属性。

**验证**：固定刚体SDF整体质量、重心和惯量与输入转换结果核对通过。

### 坐标、方向矩阵和桨重复计重

**问题**：CAD与Gazebo坐标不同；电机方向字段以列向量存储；整机网格已包含桨。

**处理**：统一转换网格、重心、旋翼位置及`I'=RIRᵀ`；方向矩阵先转置。四个桨载体的质量和惯量贡献从基体扣除，独立HQ桨作为替换资产。

### 动力和舵机信息逐步补齐

**现状**：电机为EMAX ECO II 2807 1300KV，独立桨模型HQ DP7X4X3，舵机已确认为NANGU 20KG碳刷款。

**处理**：动力系数采用集中记录的仿真基线；电池配置、性能曲线、舵机速度/供电/角度和卷线几何按后续规格更新。

## 3. ROS与PX4控制链

### 矩阵计算与飞控接入分属两个阶段

**现象**：地面ROS链能够输出B矩阵和悬停分配JSON，固定构形能飞，但活动关节飞行接口尚未接通。

**处理**：建立专用SITL程序`px4_morph`，接收当前旋翼位置与推力轴，更新PX4内部效能矩阵。位置/姿态控制、原生控制分配和电机输出继续由PX4执行。

**验证**：已在未解锁H25→X→V25→X过程中获得实际关节反馈及PX4矩阵更新序列确认。

**实现**：`a_morphing/airborne/px4-morph-geometry.patch`与`ros_control.py`。原PX4源码和基线可执行文件在专用编译后恢复。

### 临时ROS适配的采样周期较低

**现象**：早期关节消息约5Hz，矩阵计算20Hz，实测输入到发布延迟中位101.9ms、P95 190.0ms。

**处理**：活动关节接口增加C++原生Gazebo传输辅助进程，目标为约50Hz关节反馈和20Hz几何发送；当前PX4矩阵更新入口限频10Hz。

**后续**：按活动关节测试记录统计端到端周期、输入年龄与更新确认，逐步优化时延。

### 指令切换过早

**现象**：自动地面检查在关节接近X时立即发送下一构形，节点仍在平滑过渡阶段，返回busy。

**处理**：检查流程同时等待运动过渡完成与实际角度到位。

**验证**：X→H25→X→V25→X五态检查通过。

## 4. 视觉网格出现大片孔洞

**现象**：Gazebo中的机体呈稀疏碎片，桨和机臂表面缺失。

**原因**：低精度导出使用`triangles[::stride]`间隔抽取三角面。该方式直接丢弃表面，而非保持连通性的网格简化。

**处理**：当前活动关节模型使用完整源三角面；导出脚本保留全部面。重载GUI刷新网格缓存。

**验证**：模型外观恢复；当前body网格423560面，四臂分别27794、27794、27782、27782面。

**后续**：如需降面，使用保持拓扑的网格简化方法。

## 5. 活动关节首次起飞失败

### 现象与证据

操作者在QGC起飞后，飞机姿态失稳。ROS记录显示：X目标保持0°，起飞后四臂pitch偏向约40.11°限位。

原生ULog显示，解锁约4.5秒后两臂pitch已达约22.6°；随后发生姿态失败。ULog dropout为0。

本地取证目录：`a_morphing/airborne/failures/20261115_145629/`。其中保存原始ULog、控制台、ROS记录、模型SDF、补丁及SHA256。

### 定位

当前关节速度命令方案通过了无推力地面动作检查，但在旋翼推力加载后无法保持目标角，造成非指令构形变化。问题位于活动关节驱动及其带载验证环节。

### 处理

1. 强制上锁，停止日志并暂停世界，保存失败证据。
2. 设置固定机身带载试验，四旋翼目标转速575rad/s。
3. 关节改为力控制：P=40、I=10、D=0.5，输出限幅±2Nm，积分限幅±0.5。
4. 保留PX4飞行控制PID，先验证关节保持，再进行整机自动飞行回归。

以上数值为本轮虚拟关节驱动配置。

### 验证结果

带载试验的关节峰值偏差约0.43°，随后收敛到约0.02°；末三次采样均低于2°。

活动关节X构形自动回归`air_x_20261115_145936`完成起飞、稳定悬停、Land、接地及自动上锁：

| 指标 | 结果 |
|---|---:|
| 最大高度 | 4.997m |
| 最大绝对滚转 | 0.319° |
| 最大绝对俯仰 | 0.507° |
| ULog dropout记录数 | 0 |

本地证据：`airborne/load_test/result.json`、`airborne/x-force-regression.json`、`airborne/logs/air_x_20261115_145936.ulg`。

### 测试顺序调整

新活动模型按“关节无载动作 → 固定机身带载 → X自动飞行 → 小角空中变构 → 目标角演示”的顺序推进。操作者演示使用已完成对应回归的版本。

## 2026-11-19：Delta 机械臂固定台架

整机 CAD 的 B机械夹爪为 101 实体复合零件，先前合并在无人机外观网格中。按实体拆出三个主动臂、六根从动杆、末端及固定件，以球面球心和圆柱轴线提取铰点。CAD 从动杆长度均为 200 mm；交接固件中平台 500/350 参数及注释不适用于当前 CAD，因此采用 CAD 铰点的广义正逆解，保留原始源码并移植速度插补流程。

第一轮主动关节增益与台架惯量不匹配，出现振荡和到位超时，记录保存在 delta_fixed/results/diagnostics/。调整主动臂近似惯量至对角 0.0005 kg·m²、位置环 P=8 I=1 D=0.03，之后两轮序列均通过。ROS 首帧的零角由 JSON 解码成 int，JointState 要求 float，已统一显式转换。

Harmonic 台架使用主动关节实际角正解驱动从动运动学坐标，非被动受力闭环。末端与杆端误差由 Gazebo 实际位姿计算。固定机身，无 PX4、无飞行。图形界面 OpenGL 渲染器已核实为 NVIDIA RTX 4060。


## 2026-11-19：固定机身机械臂受力闭合

新增 delta_dynamics，保留原 delta_fixed。去掉从动关节和末端的 JointPositionReset，三个主动臂使用力矩驱动，六根杆上端通过 DART 原生球铰连接，下端通过等大反向三维弹簧阻尼力闭合动态末端平台。施力时计算实际作用点到各链接原点的力矩，开启全部机械臂链接重力。K=2000 N/m、D=3 N·s/m、dt=0.2 ms；该方案是有限刚度闭合，不是无限刚度理想球铰。

空载和额外 50 g 均完成完整轨迹，保持力矩与独立势能求导相符。时间步长减半静态结果一致；禁用杆端弹性/阻尼后平台按自由落体下落，排除隐藏位姿跟随。仿真移动质量、惯量和约束刚度为本轮测试设定，未作实物参数估计。测试原始状态、结果、截图及图表存于 delta_dynamics/results。

实现检查曾将地平面也纳入重力开启检查，地平面采用默认字段，导致检查误报；已限定检查实际机械臂模型的链接，未修改实验判据或数据。截图采用窗口前置后采集并恢复原活动窗口，避免截到遮挡它的应用。


## 2026-11-19：原生闭链实际兼容性与敏感性

最小模型在 yaw=0 和 0.37 rad 下测试：直接 SDF 双球铰的第二个父连接被 gz-physics 拒绝，误差与单端连接相同；增加球铰连接体并通过 DetachableJoint 创建原生固定闭合后，最小模型正常保持。随后独立 native 版本将 12 个原生球铰与六个运行时固定连接用于完整 CAD 机构，不使用手写杆端力或位姿重置。空载、50 g、50 g 且固定基座 roll/pitch/yaw=0.12/-0.08/0.37 rad 三组完整序列通过，闭合误差约 1.4 μm。六个辅助连接体共 0.06 g 已计重。

弹性版本进行单因素 K=1000/2000/4000 和 D=1.5/3/6 对照。K1000 在横移段未达到 0.5 mm 到位条件，5 s 超时；重复出现后保留失败原始状态与日志，没有放宽判据。其他四组通过。初版测试脚本遇失败直接中断，现已改为保存失败并继续后续工况。

新增 JointTransmittedWrench 采集读取的是机身到世界固定约束的六维反力，包含整机测试质量，并非独立机械臂安装法兰。以静态均值扣除后进行运动扰动对照。后续入口切换至 delta_dynamics/native，旧弹性版本保留供比较。未做飞行试验。
