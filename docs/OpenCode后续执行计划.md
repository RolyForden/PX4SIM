## 1. A模型运动分组与近似关节（第一交付）

建立独立 `px4_rtl_land_validation/a_morphing/`，不要覆盖candidate_rigid和旧参考台架。先读取123部件CAD索引、交底书和图4/5，输出一个集中配置，记录机身/四机臂部件索引、坐标、近似关节中心与轴、角度限位、质量分组及假设。

- 几何是用户自研A整机，不能套用旧UAV.STEP的±45mm关节和25度端点冒充真实值。
- 单舵机同轴双层反向预绕，H与V是同一输入的不同分支；仿真内部多个等效自由度不等于实物多个独立舵机。
- 交底书的柔性件含多方向弯曲、双TPU和滑块退让。第一版可用等效关节与弹性回复/阻尼近似，主动说明忽略的耦合；不声称做了连续体或真实绳索动力学。
- 第一轮固定机身做地面运动检查。主动位置控制与被动弹性测试应分开：强位置控制器压住关节时，不能以此证明弹性回弹特性。
- H/V目标可先按附图选可替换保守角度，Visio15/30/45度仅为示意。H↔V第一版经X复位。
- 第一版不模拟绳索接触，可用单输入到目标角的平滑映射；绳索可作为示意线显示，不能把视觉线当真实受力计算。
- 沿用临时机体系，从装配及设备朝向推断并记录坐标约定，不将方向确认作为建模前置条件。若统一改变坐标，网格、关节、COM、惯性及旋翼全部同步变换。

验收：在Gazebo实际执行X→H→X→V→X；读取真实关节角、各电机位置和轴向，保存带时间戳的请求/反馈JSON及截图。数值与解析几何核对，误差阈值事先记录。检查碰撞/限位/部件绑定，不只看动画。

## 2. ROS 2指令与真实反馈（与第一交付一起完成）

先检查现有Humble、工作空间及ros_gz/Gazebo库版本。不要把对接宿主Classic/Fortress的桥直接拿来连接容器Harmonic。

优先兼容的ROS 2—Gazebo桥，使用JointPositionController等Harmonic支持接口；若现有包不匹配，可在隔离工作空间编译匹配桥，或先用ROS节点调用容器内gz transport作为明确标注的临时适配。要实际核实依赖；需要系统级大量安装/升级时先说明范围，不重装环境。

建议接口（可按实现调整，但保持文档一致）：

- `/a_uav/morph/command`：离散X/H/V，或严格限定范围的单变量输入。
- `/a_uav/joint_states`：Gazebo实际位置/速度，不是指令回显。
- `/a_uav/morph/status`：当前构形、转换中/到位/超时、实际角度及是否近似模型。

非法构形拒绝；限制角度与变化率；超时有明确反馈。不要仅凭话题收到或publish成功判定动作成功。停止节点不自动触发飞行，也不要突然把带弹性的关节强行跳回零位。

验收：给出用户可复制的两三条启动/切换命令，发ROS指令后Gazebo实际运动，实际反馈能区分过渡和到位。保存最小脚本与launch，不生成大量流程文档。先不要求QGC新增变构按钮。

## 3. 分构形质量属性和推力效能矩阵

基于实际关节角计算旋翼位置r、推力方向d和当前COM c，在一致的FRD系中建立：

`B_i = [ (r_i-c) × d_i - k_i d_i ; d_i ]`

行顺序τx/τy/τz/Fx/Fy/Fz，输入为旋翼实际推力N；k的旋向符号必须与Gazebo电机反扭矩约定核对。该物理矩阵不能直接当作归一化PWM矩阵塞入PX4。

- V上反角时旋翼推力轴随臂转动，不能只改旋翼位置；不能仅检查6×4秩4就声称任意六轴可控。
- 按部件质量表分配运动质量；未定位0.393kg先留机身并标假设。所有构形保持总质量一致，COM和惯性随移动更新，带符号非对角项保留。
- 5个CAD实例缺质量不能当实物零质量；第一次仍可使用既有启动基线，不为补齐它们停工。原桨和HQ桨不要重复显示或计重。
- 对X/H/V分别做有界静态悬停可行性、残差及执行器余量检查；动力限制仍沿用标注借用值，不能宣称真实电机足够。

## 4. 固定H/V飞行（收到用户允许实际飞行测试后）

先在独立模型/airframe里锁住一个构形，更新SDF质量属性和PX4旋翼位置/轴向/旋向。使用PX4已有CA参数能力优先，不提前改PID或改上游控制器。先X回归，再小角H，再小角V；离线检查不通过不盲目起飞。

每次实际验证起飞、稳定悬停、Land、接地、自动上锁；保存原生ULog、事件、前后参数、模型与输入假设。用真实日志分析高度、姿态、速度、模式与接地状态；失败如实保留。沿用已有越界检测，但不要将未验证的自动Land恢复当成安全保证，严重发散应停止整个仿真。

此阶段成功也只是固定构形飞行，不叫空中动态变构。QGC虚拟摇杆是否实际操作要如实记录，不能把显示摇杆称作手飞。
